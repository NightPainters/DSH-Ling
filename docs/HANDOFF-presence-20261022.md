## 0. 一句话

**器灵把所有"自己身上发生的变更"用一个极窄的只读接口说出来；要不要因此打断主人，由别人去判断。**

对照：**器灵是传感层，主动感知层是提醒层** —— 这是 `INSTINCT-LAYER.md:68-76` 早就定下的分层（传感层只记录事实不判断，判断只在提醒层）。本接口就是这两层之间缺的那根线。

---

## 1. 为什么这件事不能拖到"有需求了再做"

| 事实 | 后果 |
|---|---|
| 器灵**要外发**（主人 2026-10-11 拍板：记忆 + 人格 + 自省进器灵且外发） | 一进 npm，**接口就是公开契约** |
| 主人拍板「保留接口到主动感知层来做打断等行为」 | 接口**现在**就得存在，否则感知层无锚可挂 |
| 公开接口**只能增不能改**（改名 / 改语义 = 破坏兼容） | ⇒ **今天就要切到最窄**：切宽容易，**事后收窄不可能** |

> 设计目标不是"够用"，是「**窄到今天就能定死，以后只靠加字段扩展**」。

---

## 2. 形态：`ctx.provide()`，不是 `class extends Service`

**照抄已有的 `dsh-ling/lib/host/mode-service.js` 的结论，不要重新论证**：

> 本插件 `apply` 是**函数形态**，且 dsh-ling 以 `file:` + Junction 加载、包内无 `node_modules`，
> `import '@deepseek-ai/cordis'` 会走 realpath 回到**本包根目录**再向上找 —— **找不到**。

两条硬约束：

| # | 约束 | 推论 |
|---|---|---|
| 1 | 必须用 **`ctx.provide()`**（零 import，由 fiber 生命周期托管，返回 disposer） | 与 `registerModeService` 同款 |
| 2 | **做不到 declaration merging**（那需要 `import '@deepseek-ai/cordis'`） | ⇒ 接口**只能靠运行时形状 + 文档约定**，没有类型层保护 ⇒ **文档即契约** |

⚠️ 另有一条既有做法必须沿用：**服务名已被占用时只记日志、不抛**（`mode-service.js:79-84`）—— 器灵被加载两遍不该导致整个插件起不来。

## 3. 服务契约（v1，冻结）

### 3.1 取用（软依赖）

```js
const presence = ctx.get('dsh-ling/presence');   // 拿不到 = undefined，**不是错误**
if (presence) { /* 用 */ }
```

**契约**：调用方**不得**因为拿不到服务而中断自己的流程。器灵缺席是正常状态。

### 3.2 `state()` — 只读状态快照

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | `boolean` | 永远返回对象；失败也是 `{ok:false, reason}`，**不抛** |
| `at` | `string` | 本快照时刻（UTC ISO） |
| `bootAt` | `string` | 器灵本次加载时刻 |
| `enabled` | `boolean` | 通知是否开启（对应配置 `presence.enabled`） |
| `pending` | `{ sessions: number }` | **有多少会话挂着未消费的变更**（＝"下次开口就会被注入"的那些） |
| `lastChange` | `Change \| null` | 最近一条变更 |

> `pending` 是本接口**最有信息量的一格**：它把"她心里压着几件事没跟你说"变成了一个数。

### 3.3 `watch(fn)` — 订阅变更

```js
const off = presence.watch((change) => { /* 同步回调，勿阻塞 */ });
off();   // 退订（是函数，不是 disposer 对象）
```

| 契约 | 内容 |
|---|---|
| 返回值 | **退订函数** |
| 回调 | **同步**；调用方不得在回调里做长活（长活自己排队） |
| 容错 | **监听器抛错不影响器灵**：逐个 try/catch，一个坏监听不拖累其余 |
| 未启用时 | 仍可调用，只是永远不触发 |

### 3.4 `recent({ since, limit })` — 补看漏掉的

```js
presence.recent({ since: '<UTC ISO>', limit: 50 })   // → Change[]，时间正序
```

有界环形缓冲，容量由 `presence.bufferSize`（默认 **200**）决定，**不做分页**。

### 3.5 `Change` 的形状 ★ 最容易做错的一处

```ts
{
  kind:  'memory' | 'persona' | 'settings' | 'tree' | string,  // 未知值必须被忽略
  at:    string,                    // UTC ISO
  code:  string,                    // 受控词表，见下表
  scope: { sessionId?: string },    // 缺省 = 影响所有会话
  count?: number,                   // 本次影响条目数（可选）
}
```

**`code` 受控词表（v1，只增不改）**：

| code | 何时发 | kind |
|---|---|---|
| `tree.changed` | 记忆树结构被改（增枝 / 改归属 / 调权重） | `tree` |
| `memory.forgotten` | 有记忆被遗忘 / 回灌 | `memory` |
| `persona.changed` | 人格层文本变了 | `persona` |
| `settings.changed` | 器灵设置变了（含总开关） | `settings` |
| `mode.changed` | 某会话挡位变了 | `settings` |

🔴 **`Change` 里绝不出现"改了什么的文本"** —— 只有元信息。三条理由：

1. 与手术门同一原则（`surgery.js:207-217`：**值本身绝不落盘**，只落字段名 + 指纹）；
2. **内容形状会变** —— 塞进公开接口就是兼容性炸弹；
3. 需要内容的消费方**自己去读**（它有权限就有，没有就没有）—— 接口不替它做权限决定。

## 4. 三条兼容铁律（**发布面文档必须原样带上**）

| # | 铁律 | 为什么 |
|---|---|---|
| **1** | **消费者必须忽略未知的 `kind` 与 `code`** | 以后加值才不构成破坏 ⇒ 这是"只增不改"成立的**唯一前提** |
| **2** | **服务是软依赖**：`ctx.get()` 拿不到就跳过，**不许抛、不许报错** | 器灵缺席是正常状态（未装 / 降级加载 / 被禁用） |
| **3** | **只增不改**：已有字段的**语义**永不改；要改语义就**加新字段**，旧字段冻结 | 公开接口改名 = 用户的升级成本 |

---

## 5. 明确不做（比契约本身更重要）

| # | 不做 | 理由 |
|---|---|---|
| **1** | 🔴 **不给"拦截权"** | 器灵**不会**因为"没人接这个通知"就改变行为。**默认行为（下次聊天注入）永远执行**。打断是感知层**听了之后自己去做**的事 —— 器灵不把决定权交出去 |
| **2** | **不暴露内容** | 见 §3.5 |
| **3** | **不暴露内部对象** | 不给 `memory` / `gate` / `settings` 句柄。给出去就等于把 `memory.db` 表结构也变成公开契约 |
| **4** | **v1 不做 ack（回执协调）** | 感知层若自己打断了一次，那次注入**仍会发生**（可能重复）。**这是有意接受的代价**：加 ack 会把接口从单向变双向，而宽接口改不动。日后加 ack **是向后兼容的**（不调用就还是今天的行为） |

## 7. 验收标准（可离线跑）

1. 服务**可被 `ctx.get('dsh-ling/presence')` 取到**，且三个方法都在。
2. **拿不到服务不抛**：删除该服务后，模拟消费者调用 `ctx.get()` → `undefined`，消费者流程继续。
3. `watch(fn)` 返回**函数**；调用后不再收到事件。
4. **坏监听不拖累**：注册一个 `throw` 的监听 + 一个好监听，触发事件 ⇒ 好监听仍收到，器灵注入流程不受影响。
5. `recent()` **有界**：塞 `bufferSize + 50` 条 ⇒ 只返回 `bufferSize` 条，且时间正序。
6. **未知 kind/code 被忽略**：手工塞一条 `{kind:'xyz', code:'zzz'}` ⇒ 消费方按铁律 1 忽略，器灵不抛。
7. `state().pending` 在"有未消费变更"时 > 0，消费后回落。
8. **`Change` 里没有任何文本内容** —— 断言对象只含 `kind/at/code/scope/count` 五个键。
9. 既有 13+ 套测试全绿。

## 8. ⚠️ 一处必须先想清的取舍

**本接口 v1 没有任何公开消费者。** 这是**刻意的，不是缺陷**：

| 方 | 发不发 |
|---|---|
| 提供方：器灵 | ✅ **外发** |
| 消费方：主动感知层 | ❌ **先不发**（主人原话："甚至有高概率永远不发"） |
| 另一个消费方：主动开口层 | ❌ 不外发 |

> ⇒ **它必须窄到"即使永远没人用也不后悔"**。这正是 §1 那句"切宽容易、收窄不可能"的由来。
