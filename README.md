# dsh-ling · 器灵

> **器灵不是每次都要重新认识你的 AI。**
>
> 把你散落在各处的历史对话请进门,让器灵长出一个**属于自己**的人格档案 —— 记忆全在本地,人格可手术、可回滚,语气可以自己生长。

一个跑在你自己电脑上的[DeepSeek Harness](https://github.com/deepseek-ai)(DSH)插件。**不是云服务,不是记忆 API**:它是给"你和器灵"用的东西。

## 本项目是什么形态

- 这是一个**本地运行的软件**(DeepSeek Harness 插件),运行在**你自己的机器**上。
- **上游不提供任何在线服务、不运营任何服务端、不托管任何用户数据**:
  作者不接触、不接收你的会话内容、记忆库或人格档案。
- **不上架任何应用商店**;仅通过 GitHub(源码)与 npm(包)分发。
- 模型与 API Key 由使用者自行提供和承担,与上游无关。
- 本项目不提供医疗、心理、法律或紧急救助服务;**如遇危机,请联络当地紧急服务或专业机构**。

**关系、标识与面向性**:

- 本项目不定义你与它的关系:它可以是同事、搭档,或其他 —— 取决于你怎么用它。
- 本插件的回答与记忆摘要**由人工智能生成**,可能存在错误,请自行判断。
- 本项目面向**具备自行配置与运维能力**的用户;不面向未成年人,也不提供任何形式的在线陪伴服务。

> **关于那道「手术门」**:亲手敲承诺句是**庄重感与自我提醒** —— 让你在改契约之前停一下、确认这是自己的决定;它**不是安全边界**(「禁粘贴」只是界面上的约定,挡不住任何有心的人)。真正把门的是**来源栅栏**:Host 必须是 loopback(或你显式写进受信名单的地址);另有一个**默认不开**的开关 `guard.allowLan` —— **一旦打开,整段局域网地址都算受信来源**(那是**放宽**,不是建议)。跨站请求直接拒,带 `Origin` 时其 host 必须等于请求的 Host(**带了但解析不出来就直接拒**),而**不带 `Origin` 的请求这条校验会跳过** —— 它不是"每个请求都必须带 Origin 且同源";再叠一道 cookie **名字**对撞 —— 期望名字按当前 Host 现算(`dsh-auth-` + 哈希),**只校验名字、不校验值的签名**。所以这道门挡的是"别的设备、别的页面"这类来源,而**本机原生进程本来就还能调用**(它也能直接读 `settings.json` 与记忆库,不算提权)—— 别的来源没有凭据就进不来这台机器上的 `/api`,敲对承诺句也没用。

> **这道门现在长这样 —— 三条手续缺一不可**:① **只在本机做** —— 判据是"这次请求没有经过任何代理"(带代理头、或连 User-Agent 都没有的请求,都算非本机 ⇒ 拒,理由码 `surgery-local-only`);② **每次启动取一次票据** —— 票据每启动轮换,只下发给本机直连的请求(`POST /surgery/ticket`),客户端首次手术前取一次、之后随请求带上;③ **原句匹配** —— 敲出的承诺句要与当初写下的那一句相符。这三条由 `lib/host/surgery.js` 里**一处** `requireSurgery()` 判定,覆盖**全部 12 条**能改人格 / 规矩 / 习惯的写面(调用点不许再各写一份;曾有一条 `wantLock` 绕过分支,已删除)。每次手术都留痕:`$DSH_HOME/logs/surgery-YYYY-MM.jsonl`(append-only,整行哈希链,改一行即断链);`GET /surgery/events` 是只读事件面。
>
> **承诺句只在本机回显**:`/state`(含面板档)、`/persona/history`、`/export` 这些读面,**带代理头**时只回 `hasSeal` 与 `phraseHidden`、不回原句,**本机直连**照旧回显 —— 所以你换台机器看面板不会因此被卡住,远端也拿不到原句。
>
> **守卫⑤ · 反代伪装 loopback**:上面那条"Host 是 loopback 就免检"有个前提 —— Host 由客户端自报、cookie 又只验名字,中间挡一层反向代理就会失效。现在凡「Host 声称 loopback、而 `X-Forwarded-For` 的最后一段是非 loopback 的代理对端」一律拒(`spoofed-loopback-host`);本机直连(无代理头)与经反向代理的正常远程访问都不受影响(后者根本不走 loopback 分支)。
>
> ⚠️ **边界如实写在这里**:以上全部是**入口侧**的把关(来源、有没有经过代理、票据、原句) —— 它们**不覆盖「本机执行权已经失守」的情形**:能在这台机器上以同一个用户跑进程、读文件的人,本来就在信任域里面(票据文件与 `settings.json` 对同机同用户可读;承诺句是**明文存储**,那把锁只造庄重、不保密)。这些防护挡的是"别的设备、别的页面、公网一侧够到这排 API",不是本机上的对手。

**三层记忆各自什么时候更新 —— 「我刚说的话,最快多久能看到」**:

| 层 | 看得到的是什么 | 什么时候变 |
|---|---|---|
| **L0 常驻人格** | 自称 / 对你的称呼 / 底线 / 规矩·习惯 / 承担(职业·职责·责任) / 语气 / 世界观 | 你改它就变(没定型时直接生效;定型后走手术门)。**会话运行中不打断** —— 改动排队,该会话回到空闲才落进注入面 |
| **L1 开场记忆** | 从全库概述里按相关度挑出的 Top-K(有预算,**永不塞全文**) | **新会话开场时定稿一次**,之后随空闲边界刷新(与下面 L2 同一把闸);库里的概述本身由概述器持续追平 |
| **L2 运行期记忆** | **本会话那一行**(格式就是「记忆·开场」里那条自己:`- [标签] (YYYY-MM-DD) 标题 —— 摘要首句 (来源: DSH 会话/短id)` —— 标题指**概述标题**,不是会话原文首句) | 本会话原文随对话累进;那一行**只在空闲边界重排**回注入面 |

**行里的「标题」从哪来**(按来源分,细节见括号里的实现):

- **DSH 会话**:该会话**第一条真人发言**经启发式清洗后的**要点句** —— 先剥掉「晚上好器灵,」这类问候与称呼前缀,「你好」「在吗」这类无实义的首句会被跳过、**往后取前 6 条真人发言里第一条有实义的**,再在句读处收尾(不切半句);都被剥空才退回首句截断。**主人手改过的标题会上锁,机器不再覆盖**(`lib\host\retitle.js` 的 `retitleCandidates()`、`lib\host\summarizer.js` 的 `summarizeDsh()`、`lib\host\memory.js` 的 `upsertOverview()` 与 `renameTitle()`)。
- **文件导入**:导出文件里**原本的 `title` / `name` 字段**,缺了才退回上面那套启发式(`lib\host\import-file.js:142,171-173`)。
- **历史会话(旧扫描)**:该会话**第一条真人发言的前 46 字**硬截,没有启发式(`lib\host\backfill.js` 的 `overviewRowFromFile()`)。

- **机制数字(默认值)**:① 概述器周期 —— 有新增才重建,否则跳过;**每 15 分钟一拍**(可配,下限 1 分钟);② 空闲刷新 —— 只有「会话空闲 + 记忆版本变了 + **距上次刷新 ≥ 10 分钟**」三条同时成立才重建。
- **所以「刚说的话」最快约 10 分钟、通常 15 分钟内**会出现在注入面,最坏约 25 分钟(刚刷过一拍 + 再等下一拍概述器)。**运行中绝不打断** —— 刷新只发生在 `运行中 → 空闲` 那一刻。
- ⚠️ **一个例外(也是"感觉它失效了"的来源)**:**深摘要定稿之后,那一行不再自动更新** —— 概述器遇到已深摘的会话会避开它,免得把厚摘要覆盖成浅版。要它重跑:记忆中心 →「记忆浏览」→ 找到那个会话 → 点「**重摘**」,几秒后那一行就会重排。
- **健忘感还有第二个来源**:越长的会话,**只取"概述标题 + 摘要首句"** —— 这一行天然比整场对话"薄",不是它没读到,而是它只被允许显示这么一行。

> **接口侧(给要接线的人)**:`GET /state`(`?sessionId=` 取某会话,`?scope=global` 取全局)返回 `snapshot`(`builtAt` / `mode` / `stale` / `chars`)、`idleRefresh`(`count` 与 `lastAt`)与 `memory.l1`(该会话当前选中的行、分数、被省略条数)。面板目前只渲染其中的**字符数 · mode · 待刷新**与 L0 预览 —— `idleRefresh` 与 `memory.l1` 有数、没露面。

## 记忆树与复盘模式

这是本插件里**跟"器灵的人格"无关、但决定"器灵想得起什么"**的那一层。

**结构**:`主干`(恒一条,主线工作流)→ `枝`(一条并行工作线,**比会话大**,一条枝可含多个会话)→ `主脉`(由多条枝**归并**出的抽象节点)→ `连边`(枝与枝之间的横向关联,如 力学 ↔ 材料科学,可带关系类型:相关 / 前置 / 对照 / 例证 / 取代)。

**为什么值得**:平铺的记忆库没有"离我多近"这个概念 —— L1 是全库裸排序,不区分"这轮做的工作"与"三个月前的闲聊",分叉会话更是**记忆真空**。记忆树把"归属"变成可检索的信号:

- **血缘加权**:检索时按"当前枝 → 目标枝"的相对位置取档 —— **同枝 1.0 / 祖先 0.7 / 旁系 0.4**,`score = 基础分 × 血缘系数 × 矛盾系数`;分叉会话照常注入,走的是它的**血缘链**而不是主干大排档。
- **不连乘**:血缘系数是**单值**,不沿路径累乘 —— 否则五层之后 `0.4^5 ≈ 0.01`,深层枝等于从记忆里消失。
- **内容零改写**(硬性不变量):**除了"主脉提炼再次采纳会覆盖上一版"这一个例外**(覆盖前自动归档),任何树操作都不改写任何一条记忆的内容;分枝 / 并脉 / 连边只增加"关系",从不"融合内容"。
- **矛盾只标记不改写**:一对记忆被判重复/矛盾时先**标记**;未复盘时检索**以较新的那条为准**(旧的一条降权 ×0.3,**不删除**;被**驳回**的与被标成**重复**的那一对不参与降权)。
- **枝系数是预留字段**:复盘期可以调(0~2,夹紧后写入并显示),但它**当前不参与检索打分** —— 返回体里明确带 `applied:false`,别以为排序会跟着变。

**复盘 — 不是一个开关,是"左会话 + 右复盘栏"这个状态**:

- 树平时**只读**(记忆中心始终只读);点「🌱 一键复盘 / 一键进入复盘」才解锁编辑,并把**复盘开场材料**(当前树 + 待理矛盾)复制到剪贴板,开个新会话粘进去就能开始。
- 解锁后可做:**改名 / 拖动换归属 / Alt+拖动只连边 / 并脉(归类到主脉) / 调权重 / 裁定矛盾 / 断续边 / 删枝**,以及快照保存·恢复;**拖动 / 连边之后可 Ctrl+Z 撤回这一步**(撤销只覆盖复盘栏的拖动与连边;记忆中心是只读的,它自己那份 Ctrl+Z 监听早已删掉)。
- **每步留痕**:写清"改了什么、为什么"(**器灵改树时 reason 必填**;你在面板上改可以留空);树改动一律记进 `branch_log`,复盘时可审计 —— 器灵侧工具的改动记在器灵名下(「鱼姬改动了记忆树」),不会伪装成你改的。
- **未同步笔数守门**:面板记着"自器灵上次开口以来累积了多少笔结构改动还没交代"。有欠账时顶部红字提示,并且**拦住"退出复盘模式"** —— 改完树必须让器灵有机会看到(「互相复盘不应该被我绕过」)。
- **注入感知**:树变了之后,`branchLogDigest()` 把**器灵还没看过**的结构改动转成中文短句,附在器灵下一次开口的注入面末尾 —— 不需要推送,一开口就知道树动过。
- **快照与撤回**:树的保存 / 恢复(`tree_snapshot`)是"大改之前的保险";恢复前会自动把当前状态另存一份,所以恢复本身也可再撤回来。

**也不必全靠手拖**:
- 「一键生成树」分两阶段 —— ① **机械分段**(按时序相邻性把全库概述切簇,零成本、确定、可复现)② **小助手/模型只做"命名"这一件语义活**,③ 你审核后才落库(建枝/主脉 + 挂会话);它**只读概述索引、只产出候选,从不改写任何记忆内容**。
- 「归并零散枝」幂等:把名字含「零散」的枝统一收进主脉「零散会话」。
- **主脉也可以有自己的记忆**:由子枝概述提炼共性,**先出草稿**,采纳才写入(采纳需先解锁)。
- **器灵侧也有自己的手**:`tree_read`(看整树 / 某枝成员 / 待复盘矛盾)、`branch_edit`(分枝 / 并脉 / 连边 / 调权重 / 删枝)、`recall`(读回会话原文,见上文)、`memory_forget` / `memory_backfill`(遗忘 / 回灌)、`rule_add`(记规矩)、`habit_propose` / `habit_resolve`(习惯提议与表态)。`tree_read` 与 `branch_edit` 的描述里写着一条纪律:**改结构必须给 reason,而且"只在主人明确要求、或正在和他一起复盘时"才动手**。

> 依据:`DESIGN.md` §6.3(记忆树结构、血缘加权与"不连乘"、内容零改写不变量)、`lib/host/memory.js`(`LINEAGE_ANCESTOR = 0.7` / `LINEAGE_SIDE = 0.4` / `CONFLICT_DOWNWEIGHT = 0.3`、`branchLogPending()` 守门、`setBranchWeight` 的 `applied:false`)、`lib/host/l1.js`(血缘档位 × 矛盾系数进打分)、`lib/host/autotree.js`(两阶段生成)、`lib/host/tools.js`(`tree_read` / `branch_edit`)。

## 找回原文:器灵能读回你当年的原话

**概述是别人替你挑的,原文才是现场。** 在 1.6 之前,器灵能"想起"的只有一行行概述 —— 想知道你当年**到底怎么说的**,只能靠猜。

`recall` 给器灵一只**档案馆查询台**,逐级下钻、一次一层:

| 给什么 | 得到什么 |
|---|---|
| `recall()` | **会话地图** —— 本机有原文的会话清单(最近活动在前) |
| `recall({q:"…"})` | **按内容找会话** —— 走宿主全文检索,直接给命中片段(想不起"这话是哪次说的"时用它) |
| `recall({conv})` | 该会话的**对话目录** —— 每轮一行:序号 · 时间 · 角色 · 前 70 字,**不给正文** |
| `recall({conv, from, to})` | 那几轮的**原文全文** |

**它不替你挑"最重要的那 1 万字"** —— 工具只给坐标系,选哪一段是器灵自己的判断(它知道自己在找什么,排序器不知道)。单次正文有上限,但**溢出必报"还剩多少轮、下一次从第几轮读起"**,绝不静默截断。

**四个不显眼、但决定成败的设计**:

- **真人判据**:只有"真人发的消息"才算一轮 —— 注入的运行时上下文、任务标记、技能目录一律折叠成一行占位,否则目录会被过程噪音淹掉(实测:一个 150 轮的会话里,真人发言只有 **5** 条)。
- **读不到时回落查库**:磁盘上没有该会话日志时(网页端导入的历史就是这样),回落到记忆库里那份,并**明说材质不同**:`⚠️ 来源:库内原文(库那份是残的 —— 只含真人消息与有正文的回复)`。
- **会话文件名代次**:匹配 `session(\.v\d+)?\.jsonl\.zstd` 并按版本号取最高一代 —— 本机三代并存(v4 / v3 / 无版本),只认 v4 会让老用户**看不见自己的旧会话**。
- **范围默认收紧**:按内容找会话时**默认只搜主人自己的会话**,越界要显式传参,且**被挡掉的条数一律报出**(静默少给等于骗人)。

**只读,零副作用**:`recall` 不写库、不改树、不进注入面。

> **底座**:1.6 同期把**网页端一年半的历史**(**1,523 个会话 / 726.7 万字原文 / 时间跨度 2025-01 → 2026-09**)补进了记忆库 —— 在此之前,它们在本机**只剩一行概述**。

## 快速开始

> 前置:**Node ≥ 22.5**(用到内置 `node:sqlite`)· 已安装 **DeepSeek Harness** 并至少启动过一次。

安装入口是官方 CLI 的 `dsh plugin add`(它在 profile 目录里转发给 pnpm,并自动把本包登记进 profile 的 `dsh.profile.bundles` 层列表)。两条路径按你的身份选一条,不要两条都走。

### A · 从 npm 安装(推荐给普通用户)

```bash

# 2) 只验证配置层,先不启动

# 3) 给 DSH 核心打一行补丁(可取证访问日志要用;幂等/可回滚)
node ~/.dsh/profiles/web/node_modules/@nightpainters/dsh-ling/tools/apply-access-log-patch.mjs
#    不打也一切照常 —— 只是访问日志为空;但**会提醒**:侧栏挂常驻 ⚠(判据 installed===false 且 reason 为 patch-missing;只有**有意关掉** config.accessLog.enabled=false ⇒ reason 为 disabled-by-config 才不染红)
#    DSH 升级/重装后需重跑一次(补丁随包被覆盖)
#    ⚠️ 从 npm 装的人跑不了 `npm test` —— 本包 `files` 白名单不含 tests/(见下)

> 插件在配置里的注册 id 仍是 `dsh-ling`,两者不是一回事。

自检安装是否成功(**下面四个脚本不在 npm 包内**,只有源码路径能用:`tools/check-install.mjs` / `tools/check-publish.mjs` / `tools/clean-archived.mjs` / `tools/check-peers.mjs`;`tools/apply-access-log-patch.mjs` 则**在包内**,从 npm 装的人也能直接跑,见上面第 3 步):

```

> `tools/check-peers.mjs` 只做一件事:复刻宿主对 `peerDependencies` 的那道闸门(判据照抄宿主语义,用的是宿主自己那份 semver),回答"**这个插件在你的宿主版本上会不会被丢进 `skippedBundles`**"。它存在的理由是宿主的行为方式:宿主对每个名字形如 `@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` 的 peer 跑一次 `semver.satisfies(宿主版本, 你声明的区间, { includePrerelease: true })` —— 判的是「**宿主版本是否落在你声明的区间里**」,**不是**"你的写法合规不合规";判不满足 ⇒ 整个 bundle 进 `skippedBundles`、**不激活**。线索分两条路径:**从命令行启动**会往 **stderr 打一行** `skipping profile bundle …`(**容易被忽略,但不完全静默**);而**应用自持 profile 的那条装载路径一个字都不打** —— 那才是真正难查的一种,表象常常只有"它突然不见了"。⚠️ 所以"改成 `>=` 就安全"是错的:**开区间同样可能不满足**(取决于宿主版本);`^` / `~` / 钉死版本只是更容易被将来的一次宿主升级甩出去。

### 数据放在哪

| 内容 | 位置 |
|---|---|
| 设置(人格档案) | `$DSH_HOME/cache/dsh-ling/settings.json`(`DSH_HOME` 默认 `~/.dsh`) |
| 记忆库 | `$DSH_HOME/cache/dsh-ling/memory.db`(SQLite,开启 WAL) |

可覆盖的环境变量:`DSH_HOME`(数据根)、`DSH_LING_DSWEB_DB`(网页端聊天记录库默认路径,UI 里也能填)、`DSH_LING_ASSISTANT` / `DSH_LING_ASSISTANT_MODEL`(小助手地址与模型名)。

> **排障用逃生开关(不是日常配置)**:`DSH_LING_GUARD=off`(须**恰好**是 `off`,小写)或设置里 `guard.enforce = false`,用于**误判把你自己锁在门外**时的临时解锁 —— 它是**整体放行** —— `/api` 的**来源栅栏 + cookie 名字对撞**,以及**手术门**(本机限定 / 每启动票据 / 原句匹配)**一起不再拦**(默认 `guard.enforce = true`),关掉期间**任何请求都不再被拦**。只该短期使用,排障完立刻恢复。`DSH_LING_GUARD=off` 只由进程环境决定、不进配置;**`guard.enforce = false` 这条不要直接写进 `settings.json`** —— 设置接口也帮不了你:它的字段白名单只放行 `persona` / `styles` 两棵子树,`guard` 这类字段会被**直接丢弃**并在响应里回报 `ignored`(见 `lib/host/api.js` 里 `/persona` 端点的字段白名单处理:`ignored` 回报被丢弃的键),不是被拒绝而是根本进不去;要改请用界面。

> **访问日志与核心补丁的总开关(同样不是日常配置)**:这套「可取证访问日志」默认**开着**,关它的键是插件配置里的 `accessLog.enabled`(**默认 `true`**)—— 在 `cordis.patch.yml` 注册行的 `config` 段里写 `accessLog: { enabled: false }`,重载后生效,启动日志会出现 `access log off`;它**只有配置键、没有环境变量**。关掉之后**退化的只有「留痕」这一件事**:那两个全局观察钩子不再挂上、不再写 `$DSH_HOME/logs/access-YYYY-MM-DD.jsonl`、日志健康读数(`accessLogHealth()`)归 `null`;而 `/api` 与 `/api/remote.mux` 的**来源栅栏照常判定与拦截**,记忆、人格、注入与工具面**一律不受影响** —— 关掉的是「记不记」,不是「拦不拦」。已经打进 `node_modules` 的**核心补丁**可以留在原地:那两行是可选调用,日志关着时就是 no-op,DSH 照常启动;要连它一起撤掉,用 `node tools/apply-access-log-patch.mjs --revert` 删掉插进去的那几行。

小助手地址三级覆盖:**界面配置**(记忆中心 → 接入历史 → 小助手地址,可当场「测试连通」)> **环境变量** > **内置默认** `http://127.0.0.1:11434/v1`。逐字段回落 —— 只填了模型名时,地址仍走下一级。

## 隐私

- 模型调用走**你自己的** DSH 配置与密钥;
- 导入的是**你自己的**对话记录 —— 请不要把他人数据导进来。
- **访问日志也只在本地**:`$DSH_HOME/logs/access-YYYY-MM-DD.jsonl` 只记"谁在何时调了哪个端点、结果如何"(来源 IP / `fwd` / Host / UA / `bytes` / 状态码 / 拒绝原因 / 设备字段),**不记请求体、不记响应体、不记 cookie 值**;查询串与 hash(可能带 token)一律丢弃;UA 截断到 200 字符、`fwd` 60、Host 120 —— 单一设备仍可跨天对上号,但**配对凭据原文一律不落盘**。设备字段是两件东西:`deviceCookie` 只说明**配对 cookie 在不在**,`deviceId` 是**摘要**而非凭据 —— `sha256(凭据原文)` 取前 16 位十六进制,同行带 `deviceIdHash:"sha256-16"` 标出这一形态(较早版本的旧行没有这个字段,其 `deviceId` 是 32 位十六进制凭据原文)⇒ **看日志时按 `deviceIdHash` 分辨时代,别把两代的行当成同一台设备** —— 与记忆树"内容零改写"同源。**覆盖范围**:`/api` 与 `/api/remote.mux` 的 upgrade;静态资源与非 `/api` 路径不记。命中**自家部署姿态自检**签名的 403 会多带 `probe:"posture"` 字段 —— 它**仍然是被栅栏拦下的**请求,标注只为免得自检被误读成入侵。没有 `user-agent` 头的行会多带 `channel:"no-ua"` —— 它只说明"**不是浏览器直连**"(进程内客户端与经远端通道进来的设备**同签名**),**不指认是哪一台设备**。

## 边界与诚实声明

1. **器灵不是意识,也不是 AGI**。器灵是"记忆 + 规则 + 模型"的合成产物。它能记住,是因为你给了它材料。**不做这个宣称,是这个项目的底线。**
2. **器灵记住的是被读过、被概括过的部分**,不是全部历史。概述会丢细节、也可能出错 —— 所以记忆**可审计、可回滚**是设计的一部分,不是补丁。
3. **模型能力的上限就是器灵的上限**。记忆层不会让一个笨模型变聪明,它只是让器灵**不再每次从零开始**。
4. **器灵不会主动找你**(当前版本)。它只在你开口时出现。
5. **不宣称首创**。记忆分层、历史导入、时间注入、反馈改语气这些方向都有先行者(见下);本项目的贡献在**治理方式** —— 把人格当一份可以签字、可以回滚、可以被历史养大的契约。
